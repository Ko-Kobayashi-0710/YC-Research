# GenAI スタートアップ DDチェックリスト

小林個人の投資観点 + a16z + Bessemer Venture Partners の知見を統合した実践チェックリスト。
YC W26以降のリサーチ・DD時に必ず参照すること。

---

## DD軸 1: 市場概況と競合環境

### 小林の観点
- [ ] 既存代替品のユーザーが「不満を持ちながらも使い続けている」理由を言語化できるか
- [ ] 競合が「なぜ今の機能止まりか」の構造的理由（技術負債・ビジネスモデル・組織）が説明できるか
- [ ] 新規参入者が模倣しても「先行者が勝つ理由」があるか

### a16z の観点
- [ ] AIによって「従来は人間でしかできなかった作業」が自動化できる市場か
- [ ] 市場の"ボトルネック"がデータ処理・判断・実行のどこにあり、AIがそこを直撃するか
- [ ] Vertical AIとしての「フルスタック化」余地（ソフト→サービス→インフラ）があるか

### Bessemer の観点
- [ ] 既存SaaSプレイヤーの"AI後付け"が通じない理由（データ・ワークフロー・UX）があるか
- [ ] ニッチ市場でも「全量を取れば$1B以上」のポテンシャルがあるか
- [ ] 競合のプライシングが「労働コスト基準」のままでAI価値を適切に反映していないか

## DD軸 2: Why Now — タイミングの必然性

### 小林の観点
- [ ] 「2年前には不可能だった技術的理由」が1文で説明できるか
- [ ] 規制・法制度の変化が追い風になっているか（金融庁・FDA・EU AI Act等）
- [ ] 先行会社の失敗事例から「今解けるようになった理由」を逆説的に説明できるか

### a16z の観点
- [ ] LLMコストの急落（$1/Mトークン以下）がユニットエコノミクスを成立させる転換点か
- [ ] GPT-4o / Claude / Gemini のAPI公開で「以前はフルスタック自前が必要だった」ものが不要になったか
- [ ] 市場の「早期採用者」（企業・消費者）がAIツールに慣れてきたタイミングか

### Bessemer の観点
- [ ] クラウド化・デジタル化が進み「構造化データが初めて大量に存在する」産業か
- [ ] COVID・リモートワーク等の外的ショックで「従来の人力ワークフロー」が崩壊した後か
- [ ] 大企業のAI内製化コストが高く、専門スタートアップへのアウトソース需要が高まっているか

## DD軸 3: 競争優位性 / Moatは何か

### 小林の核心観点（最重要）
- [ ] **"Understanding is all you need"** — データそのものではなく、データから得る「深い理解」がMoatか
- [ ] 「データを持っているだけ」では模倣可能。データ×独自解釈×顧客ワークフローへの組み込みの三位一体か
- [ ] 3年後にAIがコモディティ化した後でも守れる「人間の判断・信頼・関係性」の資産があるか
- [ ] スイッチングコストが「統合の深さ」か「学習コスト」か「ネットワーク効果」か明確か

### a16z の観点
- [ ] **Proprietary Data Loop**: 使えば使うほど独自データが蓄積され、精度が競合を引き離す構造か
- [ ] **Workflow Lock-in**: 単なるツールではなく「業務フロー全体に埋め込まれた」状態か
- [ ] ドメイン特化Fine-tuningで汎用LLMより明確に精度が高い（ベンチマーク差が≥10%）か
- [ ] 「AIが判断→人間が承認」の構造で、承認ログが再学習データになるフライホイールがあるか

### Bessemer の観点
- [ ] **Vertical Integration**: AIが提供する示唆を実行するサービスまで一気通貫で持つか（ai_armed_operator）
- [ ] 「最初の顧客10社」が競合に取り返されない程度の統合深度があるか
- [ ] 規制産業（医療・金融・法律）での認証・コンプライアンス対応が参入障壁になっているか

## DD軸 4: マネタイズと顧客獲得の戦略

### 小林の観点
- [ ] ICP（Ideal Customer Profile）が「会社名と担当者名」レベルで特定できるか
- [ ] 最初の10社は「創業者の人脈」か「コールドアウトリーチ」か、再現性があるか
- [ ] 年間契約（ARR）として計上できる構造か、プロジェクト単発で終わるリスクはないか

### a16z の観点（Copilot / Agent / AI-enabled Servicesの区別）
- **Copilot型**: 席数・ユーザー数課金。既存SaaS置き換え。CAC高め、LTV安定
  - [ ] 競合SaaSより「明確に安い or 明確に速い or 明確に精度高い」のどれかか
- **Agent型**: 成果・タスク完了数課金。従量制。初期CAC低め、拡張性高い
  - [ ] 「タスク完了の定義」が顧客と合意できているか（曖昧だと請求トラブル）
- **AI-enabled Services型**: 既存サービス価格で納品、内部でAIを使いコスト削減
  - [ ] 粗利率が従来比で何%改善するか（最低50%以上が目標）

### Bessemer の観点
- [ ] **LTV/CAC ≥ 3x** を18ヶ月以内に回収できる見通しがあるか
- [ ] Net Revenue Retention (NRR) ≥ 110% の設計になっているか（拡張の仕組み）
- [ ] PLG（プロダクト主導）かSLG（セールス主導）かが事業フェーズと合っているか
- [ ] エンタープライズ向けなら「チャンピオン（推進者）」と「経済的購買者」が別人でも進む設計か

---

## DD軸 5: サービスのコアコンピタンス及びプロダクト開発

### 小林の観点
- [ ] 「一番難しい技術的問題」を創業者がスラスラ説明できるか（理解の深さの確認）
- [ ] デモで動くものが「本番環境でも同じ精度・速度」で動くか（Wizard of Oz問題）
- [ ] 競合が6ヶ月で追いつけない「技術的ヘッドスタート」があるか

### a16z の観点
- [ ] モデル選択の判断基準（GPT-4o vs Claude vs Gemini vs fine-tuned）が合理的か
- [ ] RAG・Fine-tuning・Agentの設計選択に明確な理由があるか
- [ ] **Evals（評価基盤）** が整備されており、モデル更新時のリグレッション検知ができるか
- [ ] Human-in-the-loop の設計：AIの判断を人間がどこでどう承認・修正するか明確か

### Bessemer の観点
- [ ] プロダクトの「コア機能」に集中し、周辺機能の過剰開発をしていないか
- [ ] 顧客のワークフローに「どの深さ」で統合されているか（API連携 < ネイティブ統合 < 業務プロセス再設計）
- [ ] スケール時のインフラコスト（GPU・API・storage）の見通しと粗利への影響を把握しているか

## DD軸 6: シード期の検証項目とPMFの定義

### 小林の観点（PMFより粗利改善速度を重視）
- [ ] **PMFより「粗利改善速度」を見よ**: MRRが増えても粗利が改善しない事業は危険
- [ ] 顧客が「このサービスなしでは業務が回らない」と言うまでの期間（TTV: Time to Value）が短いか
- [ ] 解約理由が「価格」でなく「機能不足」か（価格解約は価値提案の失敗）

### a16z の観点
- [ ] **Retention Curve**: 3ヶ月後・6ヶ月後のリテンションが「フラットになっているか」（コホート分析）
- [ ] 「自発的に使い続ける」アクティブユーザーと「義務で使う」ユーザーの比率
- [ ] ユーザーが「他の同僚・会社に紹介する」行動が自然発生しているか

### Bessemer の観点（AI-native PMF 7シグナル）
1. - [ ] **TTV短縮**: 導入から価値実感まで ≤ 1週間か
2. - [ ] **使用深度**: 週1以上のアクティブ使用、コア機能の使用率 ≥ 60%か
3. - [ ] **持続性**: 6ヶ月後もユーザーが離脱しないリテンションカーブか
4. - [ ] **Second-bite使用率**: 最初の「おお！」体験の後、別の機能も使い始めるか（AI-native指標）
5. - [ ] **NPS ≥ 50**: 推奨意向が強いか
6. - [ ] **持続ARR vs 実験ARR**: 「試しに使ってみた」予算でなく「本格予算」で契約されているか
7. - [ ] **セールスシグナル**: 顧客が「他の部門にも展開したい」と言い出しているか

## DD軸 7: シード調達後の資金使途

### 小林の観点
- [ ] 「調達額 ÷ 月次Burn = Runway」が最低18ヶ月以上あるか
- [ ] 採用計画が「何を証明するための採用か」にリンクしているか
- [ ] Series A前に達成すべきマイルストーン（MRR・顧客数・NRR）が逆算されているか

### a16z の観点
- [ ] エンジニア採用 vs セールス採用のバランスが現フェーズに合っているか（PMF前はエンジニア優先）
- [ ] モデルAPI費用の増加がMRR成長と比例しているか（スケールで粗利が悪化しないか）
- [ ] GTM実験に「チャネル別CAC測定」の仕組みを組んでいるか

### Bessemer の観点
- [ ] **先にバリデーション、後にスケール**: PMF確認前に大量採用・広告投下していないか
- [ ] Customer Success（CS）への投資タイミングが「解約が起きてから」でなく「解約を防ぐため」か
- [ ] 規制産業ならコンプライアンス対応コストを初期から予算に組み込んでいるか

## DD軸 8: 初期マーケットの選定理由と次マーケットへの移行

### 小林の観点
- [ ] 「なぜそのニッチから始めるか」の答えが「創業者の経験・人脈・ドメイン知識」と一致しているか
- [ ] 初期市場が「小さく深く」検証できる規模（数百社以内）か
- [ ] 「隣の市場への移行」に必要な追加コスト・追加機能が見積もられているか

### a16z の観点
- [ ] **Beachhead → Adjacent → Mass**: ドミノ展開のロジックが論理的か
- [ ] 初期ニッチ市場で「No. 1」になれる現実的な計画があるか
- [ ] グローバル展開時の「言語・規制・文化」の違いに対応できるチーム構成か

### Bessemer の観点
- [ ] SAM（Serviceable Addressable Market） ≥ $100M あれば基本OK
- [ ] 「大市場のスライス」ではなく「小市場の完全支配」から始まる設計か
- [ ] 既存の大手SaaSが「あえて無視している」（儲からない・複雑すぎる）ニッチか

## DD軸 9: 創業以降の事業進捗

### 小林の観点
- [ ] 創業から現在までの「速度感」が業界水準と比べて速いか遅いか
- [ ] 最大の失敗から「何を学び、何を変えたか」が具体的に語れるか
- [ ] ピボット歴がある場合、「なぜピボットしたか」の判断プロセスが合理的か

### a16z の観点（YCベンチマーク）
- [ ] 1年以内に $1M ARR達成 → トップ10%
- [ ] 月次MoM 10%成長を12ヶ月継続 → 約3.1x成長
- [ ] 主要KPI（MRR・顧客数・NRR）の「グラフ」が描けるか（右肩上がりか、理由付き停滞か）

### Bessemer の観点
- [ ] **$1M ARR**突破が「見えているか」（シード終了時点の目標）
- [ ] 顧客ロゴの「質」: Fortune 500かSMBか、どちらが将来価値が高いか判断しているか
- [ ] メディア・賞・外部評価が「売上につながっているか」（バニティメトリクスでないか）

## DD軸 10: 起業の経緯と他メンバーの役割分担

### 小林の観点（最も重視）
- [ ] **「この課題にこのチームでなければならない理由」が1文で言えるか**
- [ ] 創業者が「課題を自分で経験したか」（Pain-driven）、または「圧倒的なドメイン専門性を持つか」
- [ ] 共同創業者の「意見の不一致をどう解決するか」のプロセスが健全か

### a16z の観点
- [ ] 技術創業者（CTO相当）がいるか、またはAIエンジニアとして最高水準か
- [ ] 「ドメイン専門家 × 技術者」の組み合わせ（特に規制産業）があるか
- [ ] 創業者がYC・エンジェル・業界人脈から「最初の顧客紹介」を得られているか

### Bessemer の観点
- [ ] **Founder-Market Fit**: 創業者の過去経験と課題領域が一致しているか
- [ ] 採用力：一流エンジニア・セールスを「なぜこの会社に」引き寄せられるか（ミッション・エクイティ）
- [ ] Board/Advisor に「その産業に深いコネクション」を持つ人物がいるか

## 総合評価クイックチェック（投資判断前の最終確認）

```
✅ 必須条件（1つでも欠けたら要再考）
□ Founder-Market Fit が明確
□ Why Now が1文で説明できる
□ 課金顧客が複数存在（3社以上）
□ 粗利率が改善傾向にある
□ 競合より明確に優れた点がある

🔶 加点条件（複数揃うと強い）
□ Proprietary Data Loop の設計あり
□ NRR ≥ 110% の兆候あり
□ 顧客が自発的に紹介している
□ 規制・参入障壁が高い市場
□ 創業者が業界で既知・信頼されている

🚩 レッドフラグ（要注意）
□ データを持っているだけをMoatと主張
□ PMFなしに急速採用・急速スケール
□ 解約率が高いのに新規獲得で誤魔化す
□ デモと本番環境のギャップが大きい
□ 競合を「いない」または「小さい」と過小評価
```
